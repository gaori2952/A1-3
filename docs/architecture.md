# 웹 서비스 구성과 동작

## HTML, CSS, JavaScript
HTML은 입력 폼·메뉴·결과 영역의 구조입니다. CSS는 배치·색상·반응형을 담당합니다. JavaScript는 사용자가 입력한 내용을 읽고 요청을 보내며, 결과와 상태 안내를 갱신합니다.

이 프로젝트의 HTML은 저장소 루트에, 스타일은 css/, 브라우저 동작은 js/, 서버 코드는 api/에 있습니다.

## 사용자 입력이 결과로 바뀌는 과정
1. insights.html의 질문 입력과 분석 버튼을 사용합니다.
2. js/insights.js가 질문과 해당 프로젝트의 목표·작업·이슈를 JSON으로 구성합니다.
3. fetch('/api/analyze')가 같은 배포 사이트의 Python API에 POST 요청을 보냅니다.
4. api/index.py가 경로와 본문을 처리하고 api/ai_analysis.py를 호출합니다.
5. Python은 환경 변수에서 키를 읽어 Codyssey에 Bearer 인증으로 요청합니다.
6. 모델의 choices[0].message.content를 JSON으로 해석하고 구조를 검증합니다.
7. JavaScript가 응답을 확인해 요약·다음 행동·위험 대응을 화면에 표시합니다.

서버가 오류를 반환하면 성공 카드를 생성하지 않고 안전한 안내를 표시합니다. 결과 문장은 textContent로 표시하거나 HTML 이스케이프를 적용합니다.

## Serverless Functions와 라우팅
Serverless Function은 요청이 들어올 때 서버 코드를 실행하는 방식입니다. 사용자는 브라우저에서 /api/...를 호출하고 Vercel이 Python 실행 환경을 관리합니다. pyproject.toml의 진입점은 api.index:handler입니다.

| 경로 | 메서드 | 기능 |
| --- | --- | --- |
| /api/analyze | POST | AI 프로젝트 분석 |
| /api/starter_plan | POST | AI 실행 일정 추천 |
| /api/schedule | POST | 규칙 기반 2주 일정 |
| /api/canvas_sync | POST | 요청에 포함된 개인 API 토큰으로 과제 조회 |

Python 진입점이 일반 페이지 요청도 받기 때문에 api/index.py에서 허용한 HTML·CSS·JS를 제공하고, .env와 Python 소스 파일의 공개 접근은 차단합니다.

## API 키 관리
브라우저 코드에 키를 넣으면 방문자가 개발자 도구로 확인할 수 있습니다. 키가 유출되면 무단 호출과 비용·쿼터 소진이 발생할 수 있습니다.

OPENAI_API_KEY는 서버 환경 변수에 설정합니다. Canvas 토큰은 사용자가 조회할 때만 입력하며 서버와 브라우저에 저장하지 않습니다. 코드 공유와 키 교체는 분리되며 실제 키는 저장소와 증빙에 포함하지 않습니다.

## 로컬과 배포 환경
로컬은 dev_server.py를 실행한 컴퓨터의 localhost:8000에서 동작합니다. 배포는 Vercel HTTPS URL에서 동작하고 키도 Vercel 환경 변수로 따로 설정합니다. 로컬에서 설정한 변수가 배포 환경에 자동 복사되지는 않습니다.

코드 수정 → 테스트 → GitHub main 커밋 → Vercel 자동 배포 → 배포 URL 검증 순서로 확인합니다. 환경 변수만 바꾼 경우도 재배포해야 새 실행 환경에 반영됩니다.

## 오류 원인과 수정
| 발생한 문제 | 원인 | 수정 |
| --- | --- | --- |
| 홈페이지가 API 오류 JSON으로 표시 | Python 진입점에 일반 페이지 응답 없음 | 허용된 정적 파일 제공 |
| 모든 프로젝트에 동일한 시작 작업 | 고정 목록을 반환 | 실제 AI 일정 생성과 출력 검증 |
| 오늘 할 일에 undefined분 표시 | 이전 작업에 소요 시간 필드 없음 | 값이 있는 경우에만 시간 표시 |
| 완료 작업이 보관함에 없음 | 프로젝트 상태만 검사 | 완료 작업과 모든 작업 완료 여부도 검사 |
| Canvas 과목 수 초과 | 지난 학기 포함, 필터 전 제한 | 선택 학기 필터 후 과제 조회 |
| Canvas 개인 과제 조회 | 공유 서버 토큰으로 다른 사용자의 과제 조회 가능 | 요청마다 사용자가 제공한 토큰만 사용, 토큰 저장 및 서버 토큰 대체 사용 금지 |

보관함은 이미 저장된 완료 작업도 표시하므로 데이터를 새로 만들 필요가 없습니다.
